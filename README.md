# Steerfold AI

Steerfold AI is a project portfolio intelligence application for monitoring project performance, budget, risk, forecasting, and management decision signals. Its intelligence and recommendations are deterministic and rule-based; it does not use machine learning or generative AI.

Brisk & Zip is a simulated organization, and all portfolio/project figures are simulated for demonstration. The project originated as a project management portfolio/capstone and evolved into a functional web application.

Steerfold AI began as an academic project in Project Budgeting and Scope Management at Sheridan College in 2026. It has since evolved into a functional web application demonstrating project portfolio monitoring, Earned Value Management (EVM), budget forecasting, risk analysis, decision support, and governance workflows.

The application uses a simulated organization, **Brisk & Zip**, with demonstration project data. Its analytical recommendations are deterministic and rule-based, rather than generated by machine learning or generative AI.

## Overview

Steerfold AI helps portfolio managers identify delivery pressure, compare financial performance, and review controlled budget changes in one browser-based workspace. Public users can browse the portfolio and project details, while authenticated users can manage project records and use authorized governance actions.

## Architecture

The application runs as a static browser app:

```text
Browser
  -> JavaScript application
     -> Supabase REST/Auth -> PostgreSQL (RLS and controlled RPCs)
     -> Same-origin Netlify FX Function -> Frankfurter reference rates
```

The CSV file in `app/data/` is read-only fallback data used when normal public Supabase loading is unavailable.

Analytics run on numeric organization-currency values before display formatting. View modules render those results; authenticated services handle writes. Post-write refreshes require Supabase and never substitute CSV. A visible notice identifies normal CSV fallback data.

## Security Model

Public users can read portfolio data. Project writes and Safe Import require authentication. Governance actions additionally require the appropriate assigned roles and actor-level separation of duties; a governance administrator is not a workflow wildcard.

Frontend button visibility is a user experience control only. Database authorization is enforced through Supabase Row Level Security. The browser uses only the Supabase publishable key; no `service_role` key belongs in frontend code.

Safe Import creates new projects only: no merge, update, or upsert. Server validation, commit-time conflict checks, explicit warning acknowledgements, and actor-bound idempotency protect the atomic batch. Live project IDs are database-generated; optional source IDs remain provenance, with cross-import identity only when a source namespace is provided. Import history is restricted to its authenticated owner.

## Running Locally

> **Try it online:** [Launch Steerfold AI](https://steerfold-ai.netlify.app/)
>
> The application includes a public demonstration using simulated project data. Some management and governance actions require authentication and appropriate permissions.

1. Clone the repository.
2. Open the project folder.
3. Serve the `app` folder through a local HTTP server.

VS Code Live Server or another static file server can be used. Avoid opening `index.html` directly with `file://`, because ES modules and CSV fetch requests may fail.

### Local FX Function

Display conversion uses the same-origin Netlify Function at
`/.netlify/functions/fx-rate?base=USD&quote=GBP`. A plain static server cannot
execute this function; foreign conversion then safely retains organization-currency values.

From the repository root, use Netlify Dev to serve the application and function:

```sh
npx netlify-cli dev --offline --dir app --port 3000
```

Open `http://localhost:3000/#settings`. The command requires Node.js/npm and
downloads the Netlify CLI if it is not already available. It does not deploy the site.
The function uses Frankfurter v2 daily reference rates; no browser-side provider
bypass or Supabase FX tables are used. Monetary readouts and print output use the
selected display currency when a validated rate is ready. Operational financial
inputs, stored records, and calculations remain in the organization currency.
Missing or unverified rates safely retain organization-currency notation.

## Organization and Display Currency

Organization Currency defines the currency context of budgets, EVM amounts,
forecasts, governance and uploaded amounts. Steerfold has no universal currency;
Brisk & Zip chooses CAD. Deployments can select CAD, USD, GBP or EUR. Supabase's singleton
`organization_settings` row is authoritative; it is not a browser preference.
Only authenticated Governance Admins can change organization currency. A real
change requires explicit acknowledgement that existing numeric financial amounts
will be interpreted in the selected currency without conversion. The RPC checks
the expected current currency to reject stale saves; it never rescales project
or governance values. This is a deliberate semantic setting, not historical FX.
New organization deployments must explicitly choose a currency during setup;
the database column has no product-wide default. CAD is Brisk & Zip's selection.

Display Currency is a separate browser preference. Matching organization/display
currencies require no FX request. Otherwise, validated reference rates convert
presentation only; unavailable FX falls back to the organization currency, never
to a product-wide CAD default. Ratios, rankings and stored financial values do not change.

Safe Import submits organization-currency amounts without conversion. The server
checks the active currency again at commit time, serialized against settings
changes. Historical import results retain their recorded currency (including CAD)
and idempotent replay remains valid after a currency-context change.

Account (`#account`) is separate from Settings. Signed-in users can manage their
own name/job title and avatar, use Supabase password verification/change, and sign
out. Email remains authentication-managed. Settings holds company information,
financial settings, appearance and display preferences; company edits require a
Governance Admin. Personal profiles are private, with no role assignment implied.

The local profile migration is `20261027_company_user_profiles.sql`, following
the organization-currency migration. Neither has been applied by this change.
See `supabase/validation/account_settings_rollout.md` for the read-only preflight,
approval boundary, staging acceptance checks and recovery plan. Persistent saves
must not be claimed as live-tested until that database rollout is confirmed.

The Phase 18 migration `supabase/migrations/20261026_organization_currency.sql`
is local pending review and a rollback dry-run. Do not deploy this refactor before
the separately approved database rollout. Until the authority is available,
Settings reports unavailable authority and new import reviews fail closed; public
demo readouts can still use Brisk & Zip's configured CAD fallback. Conversion
feedback stays in Settings, with no permanent global currency badge or banner. No live data migration
or historical FX conversion is implied.

## Deployment

The frontend remains a static web application. Full display-currency conversion
requires the Netlify FX Function; hosting without it safely falls back to
organization-currency values.

Recommended hosting: Netlify

Expected settings:

- Publish directory: `app`

Supabase production URL/Auth settings should allow the deployed domain where applicable.
